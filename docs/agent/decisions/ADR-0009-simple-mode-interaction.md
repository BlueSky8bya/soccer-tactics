# ADR-0009 — 단일 간편 모드: 클릭 배치 · 더블클릭 경로 · 단계(1~10) 타임라인

Status: Accepted (사용자 결정 2026-08-20)
Related: ADR-0003(엔진/도메인 — 유지), ADR-0005(히스토리 — 유지), ADR-0006(상호작용 — **부분 Superseded**), ADR-0001(제품 원칙)

## Context

QA 루프 후에도 사용자 판정: "사용법이 너무 복잡해 … 너무 복잡해서 효용성이 없어". 초 단위 타임라인·도구 레일·인스펙터·트리거 UI는 초보 사용자에게 진입 장벽. 사용자가 직접 제안한 모델: 좌클릭=우리팀, 우클릭=상대팀, 더블클릭=경로, 애니메이션마다 1~10 단계 번호(같은 번호 = 같이 시작). "자세히(고급) 모드도 두지 말 것 — 기본 하나만."

## Decision

1. **단일 모드.** 도구 레일 / Inspector / SegmentInspector / 트랙 패널 / FormationPicker / 주석 도구(화살표·구역·텍스트 생성) / HelpPanel **UI 제거**. 화면 = 상단 바 + 필드 + (▶ · 스크럽 · 반복 · 단계 칩).
2. **제스처 언어** (전부 마우스):
   - 빈 잔디 **좌클릭** = 우리팀 선수 추가, **우클릭** = 상대팀 선수 추가 (컨텍스트 메뉴 차단)
   - **드래그** = 이동 (공을 선수 위에 놓으면 그 선수가 보유)
   - **더블클릭 후 드래그** = 선수 이동 경로 / 공 패스 (끝의 선수가 수신)
   - **휙 던지기** = 달리기/패스 (드래그 스트로크를 경로로)
   - 경로 클릭 = 선택(Delete 삭제), 경로 끝 **배지 클릭** = 단계 +1
3. **단계 모델**: `Segment.step?: number`(1~10, 스키마 v1 additive). 같은 단계 = 같이 시작; 단계 n+1은 n의 **가장 느린** 동작이 끝나면 시작(자연 속도 유지 — "같이 끝나기"의 속도 왜곡 대신, 사용자 확인 없이 채택한 유일한 편차). 트리거는 `relayoutStepsInDraft`가 **파생** — 엔진/직렬화/구 문서 재생 그대로.
4. 자동 대응(⚡) 생성물(`gen-`)은 이벤트 앵커 유지, relayout 제외.
5. 키보드는 보조: Space/Home/G/Delete/Esc/1-0(단계)/Ctrl+Z·Y·S·O/?.
6. 튜토리얼 5장: 배치 → 경로 → 패스 → 재생·단계 → 끝.

## Consequences

- ADR-0006의 D7(왼손 키맵 Q/W/E/…, Alt+드래그), D5의 트랙/인스펙터 disclosure는 이 결정으로 대체. D2(스프링)·D3(히트 크기)·D4(직접 조작 우선)는 유지.
- 정밀 편집(초/오프셋/속도/수신자 수동 지정)은 UI에서 사라짐 — 도메인에는 남아 있어 후일 복원 가능.
- 삭제된 컴포넌트: Inspector, SegmentInspector, HelpPanel, GettingStarted, FormationPicker, Timeline(트랙), EntityMiniBar, TextEditOverlay, PitchStage(→ SimplePitch), pathScrub.
- 테스트는 간편 모드 기준으로 재작성(90개). 스키마 검증에 `step` 추가.

## Amendment 2026-08-20 (v2, 사용자 지시)

- **선수 투입은 Ctrl+클릭 / Ctrl+우클릭** (일반 클릭과 헷갈리지 않게 의도적 투입).
- **좌/우 상시 사이드 패널**: 왼쪽 = 기능(양 팀 채우기 · 공 투입(중앙) · ⚡ 자동 대응 · 새로 시작), 오른쪽 = 조작법(배치 / 애니메이션 모드 / 재생 섹션, 모드 꺼짐이면 흐리게).
- **🎬 애니메이션 모드 토글(하단)**: 켜야 더블클릭 드로우·휙 던지기·재생 바·단계 칩이 활성. 꺼진 상태의 더블클릭은 안내 토스트.
- **경량화**: 새로고침 = 완전 클린(자동저장/복원 없음). ☰ 메뉴·JSON 저장/열기·PNG/SVG 내보내기·Ctrl+S/O 제거. persistence 모듈은 도메인에 남음(UI 미노출).
- 튜토리얼 6장: 배치(Ctrl+클릭) → 애니메이션 모드 → 경로 → 패스 → 재생·단계 → 끝.

## Amendment 2026-08-20 (v3, 사용자 지시)

- **같은 단계 = 같이 시작·같이 끝남** (2026-08-20 사용자 최종 재확정 — 중간의 "자연 속도/조기 종료" 실험 폐기): 단계 길이는 가장 느린 멤버의 자연 길이, 짧은 멤버는 맞춰 느려진다. 과거 "짧은 움직임 5초" 불만의 실제 원인은 재생 5초 패딩(playableEnd로 해결)이었다. **고스트에서 이어 그린 움직임은 자동으로 원본 단계+1**(칩 조작 불필요), **스루패스는 수신자 도착에 동기화**.
- 단계 1~9. 애니메이션 바에서 스크럽/시간 표시 제거(▶·↺·⟳·칩만).
- 테마 라이트(웜 크림) 고정 — 다크 모드 제거. 시작 런처 창 제거(R13). 경로 배지 흐림(0.45).

## Amendment 2026-08-20 (v4, PLAN-20260821-005 승인 실행 — 사용자 구두 승인 "A-04 보류, 나머지는 계획대로")

반복 실험(그리고 → 재생 → 일부 수정 → 다시 재생) 계약:

- **단계 칩은 문서를 바꾸지 않는다**: 선택 + (사용 단계면) 시작 장면 preview만. 경로 재배정은 선택 액션 바의 1~9 picker 또는 숫자키.
- **구간 재생**: 사용 단계에 `▶ 이 단계만`(단계 창만) / `▶ 여기부터`(그 단계부터 끝까지). footer ▶/Space는 항상 전체.
- **결과 유지(A-02a)**: 일시정지·자연 종료는 현재 frame 유지("결과 화면" 표시). Home(↺) 또는 문서를 바꾸는 편집 시작 시에만 t=0 복귀. v3의 "멈추면 항상 원위치"를 대체.
- **경로 드래그 = 항상 휘기(C-01)**: 선택 상태와 무관. 그룹 이동은 라이브 토큰 드래그 전용.
- **배지 클릭 = 선택만(C-02)**: v1의 "배지 클릭 = 단계 +1" 폐기.
- **체인 상한(A-05a)**: Shift 지그재그가 9단계를 넘으면 생성 전 차단 + 이유 토스트.
- **세션 A/B 변형(A-03a)**: 헤더 A|B + 복제. 독립 EditorCore/undo, 메모리 한정 — 새로고침이면 소멸(경량 원칙 유지).
- **재생 중 시선**: ~~active 경로 강조~~ → **재생 중에는 경로/화살표/배지 전부 페이드 아웃**(사용자 지시 2026-08-20 "애니메이션 진행할 때는 화살표 안 보이게") — 움직이는 토큰이 곧 플레이. 일시정지·결과 화면·미리보기 frame에서는 경로가 phase 감쇠(past 0.22/future 0.45, active casing 강조)로 다시 보임. 고스트 농도는 전역 단계 순위 감쇠(바닥 0.18).
- **A-04(route handle)는 보류**: 수정자+드래그가 유일한 경로 작성 진입점. **2026-08-20 사용자 지시로 수정자를 Shift → Alt(왼쪽)로 교체**(누르기 편함). 브라우저 메뉴 포커스는 keydown/up preventDefault로 차단.
- 제거된 dead state: `animMode`/`timelineExpanded`/`autoReactOpen`/`theme`(uiStore), scrubGhost/animToggle CSS. v2의 "애니메이션 모드 토글" 언어는 안내에서 "경로 그리기·다듬기"로 대체.

## Amendment 2026-08-20 (v5, PLAN-007 — 겹침 선택 계약)

- **히트는 기하 후보다**: 페인트 순서가 아니라 겹치는 모든 후보(선수/공/고스트/경로)를 거리·순위 튜플(sticky 선택 > 같은 종류 내 현재 단계 > 정규화 거리 > 안정 키)로 정렬해 고른다. 배지·피커 등 인터랙티브 DOM은 여전히 DOM 우선(하이브리드).
- 수치 계약 유지: 소유 판별 .9/1.8(t=0 초기 보유자 폴백), 고스트 양보 1.2/0.9m, 토큰 2.2/1.76m, 경로 화면 7px.
- **호버 예고**: 클릭 시 잡힐 대상을 미리 하이라이트(라벨 없음 — A-02, 마우스·작성 화면 전용).
- **재클릭 순환**: 같은 지점 재클릭(6px·1.2s·직전 결과가 선택 유지 중일 때만)은 다음 겹침 후보를 선택. 드래그는 절대 가로채지 않는다(no-drag pointerup 전용).

## Amendment 2026-08-21 (v6, 사용자 피드백 — focus 범위 축소 · 투입 제스처 우선)

2026-08-21에 도입한 focus(한 엔티티의 타임라인만 선명)를 사용자가 실사용에서 되돌려 요청:
"선수 엔티티 하나를 잡으면 다른 모든 엔티티가 흐릿해 보기 힘듦."

- **focus = '움직임 편집' 상태이지 '선택' 상태가 아니다.** 경로·고스트·배지를 선택해
  `selectedSegmentId`가 생겼을 때만 나머지가 감쇠하고 히트 후보에서 밀려난다. 토큰을 고르거나
  끌거나 지우는 평범한 선택은 보드를 **전혀 흐리지 않는다**. 판정은 순수 함수
  `deriveFocusIds(selectedSegmentId, segmentOwnerId, ballId)` 하나로 단일화(`pathPresentation.ts`).
  선택된 움직임의 주인이 선수면 공도 함께 선명(플레이는 공과 함께 이동), 공이면 공만.
- **Ctrl+클릭/Ctrl+우클릭은 어떤 편집 상태에서도 첫 클릭에 선수를 투입한다.** v5까지의 "포커스
  중 빈 잔디 클릭은 편집 종료가 우선" 규칙은 **명시적 투입 제스처에는 적용하지 않는다** — 투입이
  1회씩 상실됐다(사용자: 더블클릭해야 생김). 편집 종료는 평범한 클릭(marquee → clearSelection)과
  Esc가 담당한다.
- **모드는 여전히 없다(v4 재확인).** 사용자가 "애니메이션 모드 때문"으로 추정했으나 `animMode`는
  v4에서 제거된 dead state이며, 보드는 배치·경로·재생을 한 표면에서 처리한다. 오해를 부른 푸터
  라벨 '애니메이션'을 **'전술 보드'**로 고쳐 v4의 표현 방침(모드 언어 폐기)에 맞췄다. 그리기
  (`annotate`)만이 별도 상태로 남는다(D 토글).
