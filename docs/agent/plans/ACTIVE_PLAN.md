## Decision (ADR-0009 v31로 승격)

1. **셸은 두 행뿐**: `상단바(48) / 캔버스(1fr)`. 좌·우 고정 컬럼 삭제.
2. **보드는 창을 채운다**(full-bleed). `usePitchView`가 이미 요소 aspect로 viewBox를 키우므로 늘어난 면적은 전부 좌표 있는 잔디가 된다.
3. **재생바는 보드 위에 뜬다** — `<footer>`가 격자 행을 먹지 않고 캔버스 하단 중앙에 absolute.
4. **피치는 안전 영역에 앉는다**: 마킹 스케일은 `min(w/baseW, (h − safeBottom)/baseH)`. 바가 잔디를 덮되 **경기장 마킹을 가리지 않는다**. 잔디(surround)는 여전히 창 끝까지 — 펜·포인터 좌표 손실 없음.
5. **팀 구성 / 정리·설정은 상단바 팝오버**(`팀 ▾`, `보드 ▾`). 버튼과 단축키 표기는 그대로 옮긴다.
6. **상시 조작법 패널 삭제**. 대신 `BoardHints` — `useActiveCues()`(Ctrl/Alt/Shift/Space/공/선수/경로 게이트, 이미 존재)가 켠 상태에 해당하는 줄만 보드 좌상단에 최대 3줄. 아무 상태도 아니면 **아무것도 없다**.
7. **F(zen)의 뜻이 바뀐다**: "패널 접기" → "떠 있는 크롬 감추기"(바·힌트·단계 패널). 패널이 없어졌으므로 옛 뜻은 성립하지 않는다.

## Verifiable End State

- **M1 골격** — `.shell[data-simple]`이 1열 2행. `sideLeft`/`sideRight` 규칙과 컴포넌트 소멸. 재생바는 캔버스 위 absolute, 재생 중 recede 유지.
- **M2 상단바 메뉴** — `양 팀 채우기 / 움직임 전체 지우기 / 새로 시작 / 공 휙 던지기`가 전부 접근 가능(role=button, 이름 동일). 키보드로 열고 닫힌다 — Enter가 열고, Esc가 닫으며 포커스는 트리거로 돌아온다(실측). **Space는 열지 않는다** — 앱 전역에서 Space는 재생이고 `useEditorKeyboard`가 먼저 먹는다. 이 앱의 기존 계약이라 메뉴가 뒤집지 않는다. 바깥 클릭과 Tab이 카드를 벗어나는 것도 닫는다. (화살표 로빙은 없다: 이 카드는 메뉴가 아니라 컨트롤 묶음이다 — `MenuButton` 주석 참조.)
- **M3 색인 + 맥락 힌트**(v32로 개정) — 유휴 상태에서 **한 줄 키 레일**(키 하나 + 낱말 하나, 실측 612×27px)만 서 있고 **펼친 행 0 · 켜진 칩 0**. Alt 유지 → 경로 줄, 공 선택 → 공 줄, 재생 중 → 재생 줄이 펼쳐지며 **그 키의 레일 칩이 켜진다**. `?` 오버레이는 전체 목록을 계속 들고 있다.
  · 개정 이유는 Plan Reversal Log R-4 — 원안("맥락에서만")은 첫 방문자에게 아무것도 가르치지 못했다.
- **M4 비율(실측으로 증명)** — 그려진 피치 폭이 1440에서 **921 → 1102**, 1280에서 **767 → 957**, 1024에서 **~540 → 910**. 바가 피치 마킹을 덮지 않음(3해상도 픽셀 실측).
  · 착지 수정: 초안 목표(1440에서 1130)는 **바 간섭을 무시한 값**이었다. 마킹이 바 위에서 끝나야 한다는 §4 계약을 지키면 900px 높이 창의 상한은 1102다. 목표를 낮춘 것이 아니라 **계약을 우선**했다(zen에서는 1208).
